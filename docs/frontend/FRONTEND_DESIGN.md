## 0. Decision Summary

바닥이 사라지는 술래잡기 uses one static browser application. PixiJS 8 with WebGL owns the game world. Semantic HTML, DOM, and CSS own setup, settings, results, fatal errors, focus, and accessibility text. TypeScript 7, Vite 8, Bun, Oxlint, and Oxfmt form the accepted toolchain baseline.

React, Vue, Svelte, Phaser, Tailwind CSS, a general state manager, and a general-purpose physics engine are not part of the initial baseline. The contest-submission visual direction is Coal-Twilight: a single dark palette shared by the DOM shell and the PixiJS canvas. Character, item, terrain, pirate-ship, cannonball, boulder, explosion, seawater-impact, and seven active skill-effect sprites have passed the asset ledger and now layer over the procedural renderer. Retired skill source sprites are not loaded. The rejected opaque-checkerboard sheets stay outside the runtime. Procedural action geometry remains authoritative because its direction and timing must stay readable above character art and remains the optional-asset failure fallback. Reduced-motion presentation preserves the same telegraph timing with fixed scale and rotation.

## 1. Product Surface and Scope

The primary surface is a short desktop-or-mobile browser single-player game reached through a public HTTPS link. The default entry point must reach quick start without installation, account creation, or a network service. Online multiplayer, authentication, a backend, a database, runtime LLM calls, and remote analytics are outside the MVP.

## 2. User Flow Map

The minimum user flow is load, menu, complete setup, game start, a tick-zero objective-and-controls briefing, a pausable `3→2→1` countdown, play, elimination or victory, and immediate restart through a fresh countdown. The first visit has no selected attributes, skills, or item. The menu stays a fullscreen start surface on coarse-pointer devices; on landscape viewports under 560 px tall its padding, masthead, button height, and gaps compact so `게임 시작` through `소스 코드` fit one screen without scrolling. `게임 시작` opens the setup-required dialog until the player saves exactly 20 attribute points, two skills, and one item; its primary action opens settings. The settings form scrolls on narrow or short viewports, but on coarse-pointer and narrow screens the save/cancel actions stay pinned to the bottom edge as a translucent sticky bar, short landscape viewports compact the masthead and heading so the form gains vertical room, the volume sliders grow to a 30 px touch target, and loadout cards run two columns between 561 px and 820 px while staying single-column on phones. With valid settings, the same action immediately opens the briefing while the application constructs the round behind it, then holds the prepared world at tick zero. The briefing dialog caps itself to the viewport and scrolls internally when needed, and on coarse-pointer devices its controls compress to two columns in portrait and one four-column row in landscape so the objective, controls, and confirmation reach one screen even at large and extra-large text sizes. The confirmation control remains disabled and reports loading until preparation succeeds; `알겠다요 ㅇㅅㅇ` alone reveals the arena and releases the countdown. Escape cannot bypass this gate. Settings edits remain draft values until `설정 저장`, then return to the menu, and later starts consume the last saved in-memory values. Version history is another static secondary branch: it renders concise newest-first milestones, returns through `메뉴로` or `Escape`, and restores focus to its launcher without creating URL or persisted state. The following `소스 코드` link opens the public GitHub repository in a new tab without granting the new page access to the opener. Required initialization failure disables start and enters a recoverable DOM error state. There are no application permission or authentication flows.

## 3. Routing Contract

The MVP is a single-page static application with one document route. URL parameters, query-driven game state, hash routing, redirects, and shareable configuration are not part of the initial contract. Static hosting must support both root and configured base-path builds without application routing.

## 4. Page and Layout Model

The DOM shell owns the initial menu, version history, settings, HUD overlays outside the game world, results, errors, and accessibility text. After start, the arena becomes a fixed full-viewport surface with no document scrolling; match information and round controls live either as translucent map overlays or inside the P pause layer instead of consuming layout below the canvas. Completed-round and fatal variants reuse that panel but never expose the resumable `계속` action; restart, menu, report, and sound controls remain available. Completed results place the outcome and actions before detailed statistics and omit developer telemetry and gameplay instructions. The PixiJS canvas is hidden before play and owns arena tiles, participants, items, pirate ships, two gold-and-teal treasure ships, gift deliveries, cannon and rock trajectories, impact effects, and a human-follow camera after start. The camera renders a local viewport and clamps at the projected world edge with a 7.25-tile ocean margin large enough to reveal pirate ship centers placed 5.25 tiles offshore and both treasure ships; it never shrinks the full island into one screen. Presentation uses a fixed 58-degree elevation: world depth is foreshortened by `sin(58°)`, while simulation and collision coordinates remain top-down.

## 5. State Ownership Model

The pure simulation owns round state. The application layer owns the fixed-step accumulator, countdown elapsed time, screen and round lifecycle, pre-round preparation identity, generated local seed, pause reasons, manual kill-reward trait delivery, and the applied human-upgrade history used by the local report. The DOM shell owns the initially empty six-attribute draft, two-skill and one-item drafts, setup completeness, the setup-required dialog, the objective-and-controls briefing gate, the six-choice kill-reward dialog, last-saved in-memory settings, focus, match-readable status, restart, and menu return. PixiJS owns presentation objects derived from read-only state. There is no server state or durable URL state. Presentation layers cannot mutate simulation entities directly.

## 6. Data Fetching and Cache Policy

Application data fetching and cache invalidation are `NOT_APPLICABLE`. Required static assets load from the same origin. Optional character, item, terrain, and skill-effect images start loading without blocking countdown or simulation; missing files retain their procedural fallback and the renderer reports a partial asset state. Procedural effects and the bundled background track are independent optional audio channels; either may fail without blocking the other or the game. Reusable skills own definition-specific layered cast cues, damaging skills own separate impact cues, and player-owned skill events receive bounded priority over bot voices inside the shared six-voice cap. A required renderer or content-contract failure blocks round start with a recoverable error screen.

## 7. Component Boundary Model

The application composes simulation, AI, presentation, platform adapters, and content. Simulation remains pure TypeScript and cannot import PixiJS, DOM, browser clocks, or ambient randomness. AI emits the same participant command shape as human input. PixiJS and DOM consume read-only state and events. Generic `shared`, `utils`, and framework-shaped layer hierarchies are not created without a concrete owner.

## 8. Design Token Contract

Semantic tokens must distinguish canvas background, stable tile, warning tile, void, human participant, bot participants, focus, cooldown readiness, mass state, success, danger, and disabled controls. The Coal-Twilight palette is the adopted contest-submission direction and is shared between the DOM shell (`src/styles.css`) and the PixiJS canvas (`src/presentation/arena-renderer.ts`):

- Void surface: `#0c0f0e` (page), `#141816` (canvas and arena host)
- Tile surface: generated grass and coast art keeps its natural color through every pre-impact phase; warning marker `#ffc857`; critical skull marker `#ff5c4d`
- Human identity: `#3b8cff` focus accent on one small foot-level chevron and the wider human combat bars; loaded character art never receives a duplicate procedural body disc
- Action telegraph: ShoveWindup amber `#ffc857`, ShoveActive red `#ff695c`, DodgeActive cyan `#68d8d6`, Stumbling magenta `#d58bea`
- Procedural fallback bodies retain the mass ring; loaded character art uses only explicit equipped-item badges and the human foot-level chevron, without mass or control-state glyphs beneath the sprite
- Success `#5fd6a6`, danger `#ff5c4d`, warning `#ffc857`, warm accent `#ff8f5c` for Mayhem mode

Color is never the only signal for collapse warning, player identity, item ownership, or action readiness. Collapse uses shape (diagonal cross, X-hatch), identity uses a foot-level chevron plus wider combat bars, map pickups use an overhead sparkle, and action readiness uses direction-line width and color together.

The 2.5D depth contract keeps tile tops rectangular and only exposes a dark 6–14 CSS-pixel cliff front where a supported tile has no southern neighbor. Generated coast frames retain grass, sand, and foam but remove their embedded blue water at load time; those transparent pixels reveal one viewport-wide ocean surface. Browser asset preparation composes the four cardinal coast cutouts into all sixteen orthogonal water-neighbor masks, so corners, opposite shores, three-sided peninsulas, and isolated remnants never substitute an unrelated one-edge frame. A second diagonal-only mask clips and paints concave lake and inlet corners from those same cardinal sources, and those tiles opt out of sprite overscan so an opaque grass corner cannot cover water. Stable generated terrain does not retain a procedural opaque rectangle beneath that cutout. If image access or canvas processing fails, a bounded mask-to-source-frame table avoids false water orientation; if the terrain atlas fails, the full procedural tile renderer remains the independent fallback. Character frames preserve transparent headroom; bottom-row variants compensate for the larger crop at display time so hats and round heads remain intact without making those four bodies visibly smaller. Characters and items remain upright instead of being vertically squashed, receive bounded elliptical ground shadows, and are drawn by interpolated world Y so nearer participants cover farther ones. Loaded character art suppresses the procedural collision body and circular mass ring; those shapes return only when all character art is unavailable. Map-item art stays upright with a gold pickup sparkle. Facing lines and world effects use the same projected vector plane. Seven active 512×512 alpha PNGs provide distinct cast and hit silhouettes for every reusable skill. Directional effects rotate from the projected simulation vector. Meteor Mark and Frost Field retain bounded sprites on their authoritative zones, while Aegis follows a shielded participant until shield health is gone. The 25-plus-participant mode retains the fourteen-transient-effect cap, and sprite maps reuse instances by event, zone, or actor key instead of allocating replacements every frame. Missing skill art leaves the procedural geometry visible and cannot block simulation or round start. The projection is presentation-only and cannot change support, collision, AI, replay hashes, or deterministic outcomes.

When a generated skill or cannonball texture is available, it replaces the same event or projectile's procedural world geometry instead of drawing both layers. If that texture is missing, the procedural geometry remains the non-blocking fallback.

Arc Bolt and Chain Bind keep immediate deterministic combat resolution, but their normal-motion hit presentation travels from the caster to the impact point at three world tiles per second before the impact cue fades. Reduced-motion presentation keeps a short stationary cue and does not animate the projectile path. This visual pacing cannot alter hit timing, AI decisions, replay hashes, or balance results.

## 9. Interaction and Accessibility Contract

The current kill-reward dialog uses the same Strength, Agility, Constitution, Spirit, Balance, and Willpower labels as pre-round setup. One reward level applies exactly one matching setup-point increment, including every secondary effect, and each card shows the complete `current → after` bundle. Legacy progression IDs remain below the presentation boundary for replay and report compatibility.

The input contract accepts arrow-key movement, right-click ground destinations, a mobile virtual joystick, and a standard gamepad left stick or D-pad. Desktop left-button dragging never acts as an analog joystick. A new right-click replaces the current destination; arrow, gamepad, or touch-joystick movement cancels destination travel, and a destination stops when its tile loses support. `Q/W`, the first two gamepad face buttons, and two touch buttons activate the selected reusable skills. `E` activates the shared cooldown-based Grappling Hook and does not occupy a loadout slot. `D`, the first gamepad shoulder button, and one touch button activate the single inventory slot. The desktop in-round action HUD keeps those four controls in one fixed `Q→W→E→D` vertical column; state or label changes cannot wrap them into multiple columns. On coarse-pointer devices the desktop HUD is hidden so the touch joystick and round touch buttons own the lower screen; those touch buttons mirror cooldown, mana, blocked, and empty states through the same action view models as the desktop HUD. `P` toggles a manual pause layer that owns live round statistics, controls, sound, restart, report, and menu actions; `Escape` or `계속` resumes it. Shift has no gameplay meaning. Manual pause remains authoritative across blur/focus and renderer restoration. `WASD` and `Space` have no gameplay meaning. Every adapter writes the same bounded human command state sampled once per fixed tick; direct gamepad or held-arrow input overrides destination travel, and releasing or losing focus restores a neutral vector and stops ordinary locomotion immediately. Setup offers six keyboard-native `0..20` steppers that must allocate exactly 20 points, exactly two unique combat skills from seven, and exactly one charged item from five; each stepper repeats while held after a 360 ms delay at 90 ms intervals, Ctrl/Meta-click applies five points, and coarse-pointer devices see a hold hint instead of the desktop-only Ctrl hint. The six trait cards form a two-column, three-row grid at desktop width and collapse to one column on narrow screens. They contain only the trait name, allocated count, controls, and a bounded allocation meter; repeated per-trait prose is omitted. A separate four-column, three-row summary exposes twelve derived combat values, including health and mana regeneration, with one meter per value linked to its authoritative source trait; on narrow or coarse-pointer screens that summary collapses behind a toggle row that still announces remaining points, so the steppers reach the first viewport. Remaining points are announced live and save is disabled until allocation is complete. Settings do not repeat the complete build in a second summary banner. Skill and item cards separate compact cost, cooldown, charge, and targeting metadata from the concrete effect description. The starting item occupies `D`; map pickups replace the depleted slot and cannot be collected while it retains charges. The in-round overlays expose health, mana, nearby combat bars, selected-skill and Grappling Hook cooldowns, mana affordability, item charges, control states, and effective stat bonuses; on coarse-pointer devices the combat readout sits in a compact three-column strip below the renderer status instead of covering the touch controls, and the aiming hint moves above the touch buttons so it cannot hide them. The pause layer accumulates actual human path distance, health damage dealt and received, shield absorption plus its share of attempted damage, active slowed ticks, and selected-skill use counts from authoritative step frames and events; on coarse-pointer devices the pause panel compresses telemetry and round statistics into two columns and collapses the controls guide behind a toggle so resume, restart, and menu actions plus core values reach the first screen, and in landscape it widens to three statistic columns, a four-column action row, and five telemetry columns so the same core fits the shorter viewport. Desktop pause trims panel gaps and statistic-cell padding so the full layer, including the controls guide, fits a standard 800 px viewport. A credited elimination pauses simulation and opens six keyboard-native radio choices: Pressure, Stability, Mobility, Reflex, Vitality, and Focus. Every uncapped trait is immediately available; there are no prerequisite paths or skill-rank rewards. Every reward card exposes current rank, each affected combat value as `current → after`, and a two-state rank meter; the after value remains textually labeled as well as color-highlighted. The dialog owns bounded internal scrolling on short screens, and its save action remains reachable. Saving queues one stat command and resumes only when visibility and renderer state also permit it. Completed, inactive, Falling, or Eliminated human state wins over the dialog and cannot accept a choice. `Q/W/E/D` enter a shared visible aiming state for directional and ground actions. While aiming, arrow keys move the target instead of the participant; the same action key or `Enter` confirms, `Escape` cancels, pointer hover updates the same target, left-click confirms, and right-click cancels. Confirmed out-of-range ground actions approach until valid, while a new movement input cancels that approach and becomes ordinary movement. Self-target actions bypass aiming and execute on the next simulation command. Gameplay action keys are ignored when an input, link, or button owns focus. Window blur and document visibility loss clear held input and pause the scheduler. The complete app shell disables text selection and native image dragging while preserving buttons, tabs, steppers, ranges, and keyboard focus behavior.

Browser context menus are suppressed throughout the game application so right-click remains game-owned on menu, settings, scoreboard, history, and arena screens. The active arena's more specific handler still resolves destination movement or targeting cancellation before the canceled event bubbles to the application root.

The Grappling Hook row shows its 10.5-second base reuse time while ready, switches to the live one-decimal remaining cooldown after use, and mirrors blocked or cooldown state on the compact touch action.

The fourth settings tab owns player preferences rather than simulation tuning. It offers four explicit text-size choices, a 0–100 sound-effect control defaulting to 50, and an independent 0–100 background-music control defaulting to 50. Both audio controls share a perceptual curve where 0 is silent, 100 is full output, and 50 maps to -8 dB, the former level-80 output. The music bus applies its separate 0.08 reference trim, so equal visible values do not imply equal raw gain. All three apply immediately, persist only in browser-local storage, tolerate unavailable or malformed storage, and never enter replays, reports, hashes, or bot decisions. A compact source credit remains visible with the music control. The public and development DOM share this contract; no tuning lab is exposed.

Settings navigation is a four-card ARIA tab list: Attributes, Skills, Items, and Lab. Only one tab panel is rendered at a time; arrow keys, Home, and End move between available tabs. Attributes is always the entry panel and shows current derived weight adjustment, health, mana, movement, cooldown, outgoing force, knockback resistance, and control duration alongside each attribute's exact next-point delta. The internal mass multiplier never appears as a player-facing unit: neutral reads `기본`, and Strength investment reads as a percentage above that baseline. Lab and its tab exist only in development builds.

Each starting-attribute card uses one compact horizontal stepper ordered as decrease, current value, and increase. The controls retain explicit per-attribute accessible names and disabled states at the remaining-budget boundary. Derived-combat labels retain readable minimum width while long values wrap only at word boundaries, so a value can never squeeze a Korean label into one-character vertical fragments. Starting-skill and starting-item cards keep full-card native input ownership while hiding the redundant checkbox or radio glyph; selection is communicated by the card's blue border, and keyboard focus retains its own visible outline. Skill cards add one decorative repository-owned icon in the same 64-pixel visual slot as item art and two separate text lines: mana plus cooldown first, then the concrete range, damage, knockback, control, radius, delay, or duration that applies. Text remains the complete contract when decorative art is unavailable.

Starting-attribute summaries, current effects, and next-point deltas render one effect per visual line. They do not join unrelated values with middle dots, and the line separation remains intact at narrow widths. The compact Skill Efficiency combat-stat cell is the sole paired-value exception: it keeps `대기 N% · 마나 N%` on one line and exposes a mouse and keyboard tooltip defining cooldown wait and mana consumption.

Starting-skill and starting-item cards use the same three-level reading order: name, compact resource or targeting chips, then a bordered effect panel. Major skill clauses and item effects render as separate rows inside that panel instead of one punctuation-separated paragraph. The rows are a DOM projection of the existing definition-derived descriptions and do not own duplicate balance values.

The three reading levels occupy shared card tracks rather than vertically centering one variable-height copy block. Skills and items use two cards per desktop row and one card per narrow row. Every card reserves the same title and metadata rows, then places the decorative art and bordered effect list on one body baseline. Cards do not keep an artificial fixed minimum height: every desktop row stretches both cards to the intrinsic height of its longest effect list, while title, metadata, art start, and effect-panel start remain aligned. Narrow layouts retain the same order with smaller art instead of returning to content-dependent centering.

Character motion is a presentation-only projection over render-frame velocity, action state, and accepted skill-use events. Every actor receives a stable phase offset for walk lift, weight shift, and alternating foot contacts. A short cast pose anticipates and releases toward facing direction, while Shove, Dodge, Stumbling, Grapple Pull, and Falling keep priority. `prefers-reduced-motion` disables continuous walk and cast transforms. The motion layer cannot write simulation state or alter collision and replay outcomes.

## 10. Loading, Empty, Error, and Disabled States

Boot has loading, ready, unsupported-renderer, required-content-error, and retry states. Setup disables start only when normalized configuration cannot be produced. Playing exposes paused and fatal-invariant states. Optional media failure does not create an empty game state.

## 11. Form and Validation Model

Settings are local client inputs validated at the DOM boundary and normalized again by the application contract. There is no backend validation. Invalid user-controlled values are constrained with visible feedback; invalid project-owned content blocks start rather than silently inventing defaults.

## 12. Responsive and Layout Rules

The layout supports narrow mobile viewports without covering setup controls. A coarse pointer or viewport at or below 820 px reveals an arena-overlay virtual joystick and four skill/Hook/item buttons; touch may also drag anywhere outside those buttons. Desktop mouse dragging is not mapped to that touch-only analog path. Once a round starts, both desktop and mobile arenas use the full dynamic viewport, honor safe-area insets for overlays, and remove page scrolling instead of stacking controls below the canvas. The pause and six-choice trait panels own bounded internal scrolling on short screens. Pause controls use two readable columns and round statistics use three columns at desktop width, then reduce columns at narrow breakpoints without splitting labels into vertical fragments. DOM controls remain at least 44 CSS pixels, and device-pixel ratio stays capped by measured performance policy. Physical-device and safe-area testing remain release evidence gates rather than inferred support claims.

## 13. Observability and Analytics

Remote analytics, session replay, advertising, and automatic error upload are excluded. The normal HUD contains only match-readable state. DEV bootstrap creates one collapsed `data-development-only` panel for tick, rate, position, seed, and state hash; production HTML contains no panel markup and production never creates or updates those outputs. Fatal errors may show copyable non-secret reproduction metadata without uploading it. Completed rounds may copy a local versioned playtest record with seed, normalized settings, result, and state hash; this is a user-triggered clipboard write, not analytics. Separately, the scoreboard persists only a bounded non-secret summary of the latest fifty completed rounds in this browser and never uploads it.

Product `0.84.0` loads four fixed 768×768 participant-motion atlases in parallel with the original static atlas. The presentation layer selects idle, walk, cast, or hit by authoritative render action and accepted event state; it does not infer combat outcomes or mutate simulation state. Missing motion assets fall back per participant to the existing static texture. Reduced-motion retains one-frame cast and hit state changes but does not cycle walking frames.

Product `0.86.0` makes `GameSession` the owner of the active frame commit. `ArenaRenderer` targeting and camera setters retain state and coalesce non-loop invalidations instead of submitting the complete Pixi scene immediately. Paused frames are event-driven, countdown rendering follows visible number changes, and the DOM HUD receives a 10 Hz telemetry projection. Pointer capture loss clears movement, countdown movement warmup is shared by keyboard and pointer, arena bounds own target hover, and gamepad aim repeat is time-bounded.

Product `0.90.0` replaces raw skill impulse labels with definition-derived base travel distance in tiles. Comma-separated targeting, damage, knockback, stun, stumble, and recovery effects remain separate card rows; the DOM owns formatting only and does not duplicate combat values.

Product `0.192.0` advances simulation to `79.0.0` while content remains `48.0.0`. Camera shake is removed from every combat event. Arc Bolt and Chain Bind keep their generated projectile visible at six tiles per second and apply damage and control when the projectile tip first reaches the target body's outer edge in both normal and reduced-motion presentation.
